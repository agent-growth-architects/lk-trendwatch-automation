# Запуск и проверка пакета

## Среда

Локальные инструменты рассчитаны на Python 3.9 или новее, macOS либо Linux. Они используют стандартную библиотеку, включая fcntl для блокировки записи и zoneinfo для часовых поясов. Нативная Windows без адаптации блокировки не поддерживается; среда Linux подходит для проверки.

Агенту отдельно нужен разрешённый доступ к Instagram и способ запускаться по расписанию. Перед работой прочитать текущую документацию своего браузерного инструмента. Старые идентификаторы вкладок, команды CUA и настройки чужого компьютера не переносить. Браузерный сбор выполняется агентом; автономный универсальный scraper в пакете отсутствует.

Архив предназначен для нового экземпляра мониторинга. В нём нет накопленной рабочей базы, приватной статистики LK, видео, cookies или ключей. Для продолжения прежней базы нужна отдельная согласованная передача истории и доказательств. Без неё начать новые наблюдения с фактической даты; не восстанавливать старые дни из чисел в README.

## Подготовка

Распаковать архив в постоянную папку. Все команды ниже выполняются из корня lk-trendwatch-automation. Для production выбрать отдельный постоянный каталог вместо data, если это требуется средой.

```bash
python3 -m unittest discover -s skill/tests -v
python3 skill/scripts/trendwatch_data.py init --project data --registry registry.json --timezone Europe/Moscow --name 'LK Urban Dress'
python3 skill/scripts/trendwatch_data.py validate --project data
python3 skill/scripts/trendwatch_data.py queue --project data --output data/queue.json
```

Убедиться, что сохранены 30 одобренных брендов и четыре неизвестных handle. Повторно проверить идентичность и текущую доступность известных профилей. Поле status_at_export относится к историческому срезу; текущий status требует новой проверки. LK как собственный аккаунт указан в цели, но не добавлен скрыто к 30 конкурентным брендам. Его регулярное включение в этот список согласуется отдельно.

## Сбор и обработка

Предпочтительный переносимый интерфейс: агент собирает подтверждённые записи и формирует VERIFIED_BATCH_JSON по схеме из skill/references/data-and-snapshots.md. Пример в скилле синтетический: не загружать его как реальные наблюдения. Источники сохранить рядом с пакетом конкретного запуска.

```bash
python3 skill/scripts/trendwatch_data.py ingest --project data --input data/runs/RUN_ID/verified-batch.json
python3 skill/scripts/trendwatch_data.py validate --project data
python3 skill/scripts/trendwatch_data.py render --project data
```

Заменить RUN_ID реальным именем папки. После обнаружения новых роликов снова построить queue. Для продолжения восстановить сохранённые страницы, проверить ещё допустимый возраст и собрать недостающие данные с текущим временем. Обработчик блокирует запись на время сохранения, но не предотвращает одновременную работу двух браузерных сборщиков; нужен один владелец очереди.

Базовый render строит временные серии. Полный статус запуска и покрытие агент должен добавить по фактическим данным. Он сохраняет execution.json с началом, концом, статусом, охватом профилей, числом обнаруженных и измеренных роликов, новыми аудиозамерами, ошибками и остатком очереди. В verification.json записать конкретные проверки и их результаты. При сбое источник отмечается отдельно от успешной проверки структуры прежних данных.

## Совместимость с исходным форматом браузерных доказательств

В helpers/ лежат два вспомогательных скрипта исходного мониторинга. В ingest_browser_evidence.py заменён только абсолютный путь импорта скилла на путь относительно пакета. Браузерные эксперименты, привязанные к исходной сессии и историческим файлам, не включены.

Если агент сохраняет исходный формат evidence.json, доступны команды:

```bash
python3 helpers/ingest_browser_evidence.py --project data --evidence data/runs/RUN_ID/evidence.json
python3 helpers/finalize_daily_run.py --project data --run data/runs/RUN_ID
python3 skill/scripts/trendwatch_data.py validate --project data
```

Эти helpers принимают конкретную структуру исходного коллектора. Обязательные верхние поля: started_at, finished_collection_at, profiles, details, audio, profile_progress. Страницы profiles содержат handle, url, observed_at, profileText и rows; строка сетки содержит code, url, display и при необходимости observed_at. Details связываются с сеткой через grid_handle и code; дата берётся из единственной записи published с datetime. Реакции читаются из reactionButtons. Аудиозаписи должны содержать совпадающие requested_audio_id и audio_id, url, observed_at и display. Точный контракт преобразования следует читать в helpers/ingest_browser_evidence.py перед применением.

Сначала завершить сбор доказательств, затем запускать finalizer. Он распознаёт blocked_source_access и статусы с префиксом partial_. Другие неполные состояния не следует передавать как готовый запуск. Если используются другие форматы или новый сборщик, заполнять стандартный verified-batch и собственный журнал, а вспомогательные скрипты не считать универсальным интерфейсом.

В исходном finalizer часть подписей предназначена для восстановления доступа к Instagram. При другом типе частичного сбоя агент обязан проверить, что текст соответствует фактической причине. Корректность состояния проверяется отдельно от полноты прохода и правильности пояснений.

## Проверки при переносе

1. Пройти штатные тесты скилла в новой среде. Они используют синтетические данные и временные папки.
2. Через текущий разрешённый источник проверить хотя бы профиль, свежий Reel с точной датой и связанную аудиокарточку. Недоступные поля оставить неизвестными.
3. Сохранить небольшой реальный пакет, обработать его и повторить ingest. Число снимков не должно увеличиться при повторе того же пакета.
4. Открыть сохранённую базу и отчёт, сверить выбранный Reel, цифры, время и аудио. Проверить ссылки из формата, который получит читатель.
5. Провести полный обход списка. Отдельно посчитать 30 одобренных записей, подтверждённые профили, доступные сетки, проверенные даты, допустимые ролики, успешные снимки и пробелы.
6. Только после разрешения владельца настроить один ежедневный запуск на 10:00 Europe/Moscow. Для Codex использовать штатный инструмент автоматизаций и продолжение выделенной задачи; сначала проверить отсутствие существующего дубликата. Не включать второй запуск поверх исходного экземпляра.
7. Проверить сохранённое расписание и фактический результат следующего планового запуска. Семь календарных запусков подряд использовать как предложенное окно наблюдения за устойчивостью. Пропуски должны оставаться видимыми.

Правила времени, возрастных дней, округления, исправлений дат и сравнения описаны в skill/references/data-and-snapshots.md. Готовый текст задания находится в AUTOMATION_PROMPT.md. Он требует абсолютных PACKAGE_DIR и PROJECT_DIR принимающей среды.

## Файлы пакета

| Файл | Назначение |
|---|---|
| README.md | Регламент для человека и согласованные границы |
| index.html | Автономная версия документов для чтения и пересылки |
| AUTOMATION_PROMPT.md | Текст ежедневного задания |
| registry.json | 30 одобренных брендов, без рабочей истории |
| skill/ | Trendwatch v2, методика, шаблоны, расчёты и штатные тесты |
| helpers/ | Преобразование исходных браузерных доказательств и выпуск отчёта |
| SOURCE_STATUS.json | Датированный срез состояния исходной настройки |
| CODE_PROVENANCE.json | Происхождение и контрольные суммы кода |
| PACKAGE_VERIFICATION.json | Результат проверки именно передаваемого пакета |

Сначала прочитать README, проверить среду и выполнить малый живой сбор. Успех локальных тестов подтверждает обработку данных, а доступность источника и запуск по расписанию проверяются у получателя.
